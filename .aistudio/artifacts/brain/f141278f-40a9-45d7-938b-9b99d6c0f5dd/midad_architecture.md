# وثيقة المعمارية التقنية والتصميم الهندسي الشامل
## نظام مِداد — MIDAD AMDS
### نظام الكتابة العامة الذكي للرابطة المغربية للتنمية والتضامن (AMDS)
**الكاتب العام:** ذ. عماد المزراوي  
**الشعار الرسمي:** «نكتب، نوثق، ننظم، ونحفظ ذاكرة الرابطة.»

---

## 1. حزمة التقنيات (Technology Stack)

| الطبقة (Layer) | التقنية المختارة | التبرير الهندسي |
| :--- | :--- | :--- |
| **واجهة المستخدم (UI/UX)** | React 19 + TypeScript + Vite | أحدث معايير الأداء، نوعية بيانات صارمة (Strict Typing)، وسرعة بناء فائقة. |
| **التصميم والأنماط** | Tailwind CSS v4 + Motion | تصميم مؤسساتي حديث ونظيف، تحكم فائق في أنظمة RTL، وحركات سلسة بدون مبالغة. |
| **غلاف الحاسوب (Desktop Shell)** | **Tauri v2** (مع بنية تجريدية تدعم Electron كبديل) | استهلاك ذاكرة منخفض جداً (~40MB مقابل ~200MB في Electron)، أمان رستم (Rust)، وحجم مثبت لا يتجاوز 15MB. |
| **إدارة الحالة المحلية** | Zustand + Dexie.js (IndexedDB) | إدارة حالة موحدة وسريعة مع قاعدة بيانات محلية لدعم العمل أوفلاين (Offline-First). |
| **الخلفية السحابية (Cloud Backend)** | Firebase (Authentication, Firestore, Storage) | قاعدة بيانات سحابية متزامنة فورياً، قواعد أمان صارمة (ABAC)، وإدارة ملفات آمنة. |
| **الذكاء الاصطناعي المؤسسي** | Google GenAI SDK (`@google/genai`) | استخراج البيانات، الفحص الدقيق، صياغة الوثائق المعتمدة، وتحليل المستندات مع منع الهلوسة. |
| **محرك الوثائق والتصدير** | PDFKit / html2pdf / JSZip / SheetJS | توليد ملفات PDF, DOCX, XLSX, ZIP محلياً بجودة طباعة مؤسساتية ومعايير RTL عربية. |

## 2. مقارنة تقنية معيارية: Tauri v2 مقابل Electron

| معيار المقارنة | Tauri v2 (الخيار الموصى به والمصمم له) | Electron | التقييم لبيئة عمل AMDS |
| :--- | :--- | :--- | :--- |
| **محرك العرض (Runtime)** | يستخدم **Microsoft Edge WebView2** المدمج في نظام Windows 10/11 | يشحن نسخة كاملة من Chromium متكررة مع كل تثبيت | **فوز Tauri**: لا يستهلك موارد الجهاز ولا يثقل حاسوب الكاتب العام. |
| **حجم حزمة التثبيت (Installer Size)** | **~8 إلى 15 ميجابايت** | **~85 إلى 150 ميجابايت** | **فوز Tauri**: توزيع سهل وسريع عبر البريد أو الرابط الرسمي. |
| **استهلاك الذاكرة العشوائية (RAM)** | **~35MB - 60MB** عند التشغيل | **~180MB - 350MB** | **فوز Tauri**: سلاسة تامة أثناء العمل المتزامن مع Office ومتصفحات الويب. |
| **التعامل مع ملفات النظام والأمان** | واجهات Rust محمية بـ Scopes صارمة | Node.js IPC يتطلب تأميناً دقيقاً لمنع ثغرات XSS-to-RCE | **فوز Tauri**: حماية أمنية مضاعفة للمستندات والوثائق المؤسساتية. |
| **سهولة التحديث التلقائي** | مدمج (Tauri Auto-Updater مع توقيع رقمي) | Electron-updater يحتاج لإعداد خوادم مخصصة | **تعادل**: كلاهما يدعم التحديثات التلقائية لنظام ويندوز. |

**القرار المعماري:** نبني الواجهة والمنطق الأساسي عبر طبقة تجريد `DesktopBridgeInterface`، مما يتيح تشغيل التطبيق في Tauri v2 مباشرة مع جاهزية كاملة للعمل كـ PWA أو Electron دون تعديل سطر واحد في منطق الأعمال.

## 4. معمارية Firebase & Firestore Collections

المخطط الهيكلي لقواعد البيانات المصمم لمنع التكرار وتطبيق مبدأ **Single Source of Truth**:

1. **`organization`**: وثيقة الهوية الرسمية للرابطة (الاسم، الكاتب العام، الشعار، الألوان، أرقام التواصل).
2. **`users` & `roles`**: بيانات المستخدمين وأدوارهم المؤسساتية (Super Admin, Secretary General, Branch Manager, Editor, Viewer).
3. **`activities`**: النشاط المؤسساتي الكامل، حالته في دورة الحياة، أهدافه، وتاريخه ومكانه الموحد.
4. **`activity_versions`**: سجل الإصدارات المتتالية لكل نشاط مع الفروقات (Diffs) ومن قام بالتعديل.
5. **`branches`**: فروع الرابطة (تطوان، طنجة، الرباط...) وبيانات مكاتبها وأنشطتها.
6. **`members`**: سجل الأعضاء الرسميين، مع تمييز دقيق للأعضاء المقترحين من المستندات (`suggested_by_ai`).
7. **`partners`**: الشركاء المؤسساتيون، اللوغوهات، والأنشطة المشتركة.
8. **`documents`**: المراسلات والتقارير والوثائق مع الترقيم التلقائي المحمي (Sequencing).
9. **`certificates`**: سجل الشهادات برقم تعريفي فريد ومحمي ضد التكرار.
10. **`institutional_memory`**: نصوص القوانين الأساسية، النظم الداخلية، ومحاضر الجموع العامة كمصدر وحيد للحقيقة.
11. **`audit_logs`**: السجل غير القابل للتعديل للعمليات الحساسة (إنشاء، اعتماد، حذف مؤقت، تصدير).
12. **`sync_queue`**: طابور العمليات غير المتزامنة المنفذة أثناء انقطاع الإنترنت.

## 5. معمارية الذكاء الاصطناعي المؤسسي «اسأل مِداد»

1. **مبدأ الصفر-هلوسة (Zero-Hallucination Policy)**:
   - النموذج ممنوع تماماً من توليد أسماء، تواريخ، أرقام حضور، أو شركاء غير واردة في قاعدة البيانات أو الملفات المرفقة.
   - في حال غياب المعلومة، يعرض النظام بوضوح: *«المعلومة غير متوفرة في السجلات الرسمية»* أو يطلب التأكيد اليدوي من الكاتب العام.
2. **محددات المصادر (Data Provenance)**:
   لكل حقل علامة مصدر صريحة:
   - `User Entered` (مدخل يدوي)
   - `Extracted` (مستخرج من ملف أو مسح ضوئي)
   - `Institutional Memory` (مستند مرجعي معتمد)
   - `AI Suggested` (مقترح ذكي ينتظر الاعتماد الصريح)
   - `Approved` (معتمد رسمياً من الكاتب العام)
3. **محرك الفحص والمطابقة (Review Engine)**:
   يقارن بين الوثائق (مثلاً: رقم الحضور في التقرير الأدبي مقارنة بلائحة التوقيعات الفعلية)، ويرسل تنبيهاً ذكياً عند وجود أي تضارب.

## 6. محرك التصميم الموحد والهوية البصرية (Design Engine)

- الهوية الرسمية لـ **AMDS** مخزنة كقاعدة قياسية (الأحمر المغربي، الأخضر الملكي، الذهبي التوثيقي، والأبيض).
- بمجرد إدخال معطيات النشاط مرة واحدة، يقوم المحرك بإنشاء هوية بصرية مشتقة ومنسجمة تشمل:
  1. الملصق الرسمي (Poster)
  2. بطاقة الدعوة الرسمية (Invitation)
  3. برنامج النشاط المفصل (Program)
  4. البلاغ الإخباري (Announcement)
  5. منشورات شبكات التواصل (Social Cards)
  6. شهادات الحضور والتقدير (Certificates)
  7. غلاف التقرير التوثيقي (Report Cover)

## 7. استراتيجية العمل بدون إنترنت (Offline-First) وإدارة التعارض

- يتم تخزين البيانات النشطة في **IndexedDB** محلياً على حاسوب المستخدم عبر Dexie.js.
- أي تعديل يتم أثناء انقطاع الاتصال يُسجل في طابور محلي مشفر `offline_mutations`.
- عند استعادة الاتصال:
  - التحقق من رقم النسخة (Version Check).
  - إذا تم تعديل السجل من طرف آخر، يُعرض فوراً مربع **إدارة التعارض (Conflict Resolver)** بمقارنة جنب إلى جنب (Version A مقابل Version B) مع خيار الدمج أو اعتماد نسخة الكاتب العام، دون أي مسح صامت للبيانات.

## 8. خريطة طريق التنفيذ (10 المراحل)

- **Phase 1 (المرحلة الحالية المباشرة)**: Desktop Shell + تكوين Firebase والمصادقة + مركز الهوية (Brand Center) + لوحة التحكم التأسيسية.
- **Phase 2**: إدارة الأنشطة (Activity Core & Workspace) + دورة الحياة والنسخ والأرشفة.
- **Phase 3**: مدير الملفات والمستندات المحلية والمستودع السحابي + تجميع Activity Pack.
- **Phase 4**: ذكاء المستندات (OCR, PDF/Word Extraction) + الذاكرة المؤسسية + مركز «اسأل مِداد».
- **Phase 5**: محرك التصاميم الذكي (الملصق، الدعوات، الشهادات، بطاقات التواصل).
- **Phase 6**: محرك التقارير الموسع وتصدير PDF/DOCX/XLSX/ZIP.
- **Phase 7**: إدارة الأعضاء والفروع والشركاء مع التمييز بين المعتمد والمقترح.
- **Phase 8**: إدارة الاجتماعات والمراسلات المرقمة والمهام والتقويم المؤسساتي.
- **Phase 9**: تدقيق الأمان وسجل العمليات الحساسة وإدارة التعارض والبحث العام (Ctrl+K).
- **Phase 10**: التحسينات النهائية، اختبارات الأداء الميدانية، ومثبت Windows النهائي (.msi / .exe).
